# Central AI Service

The `AiService` manages natural language copilot tasks, hazard incident auditing, and autonomous action planning. It executes background evaluations to generate detailed reports and propose safety overrides.

## Configuration
`AiService` retrieves the following configurations on start:
- `GEMINI_API_KEY`: The API authorization key used to authenticate request packets to Gemini APIs. If not found in the dynamic configuration store, it defaults to the local environment variables.

## Dynamic Mode Tiers
1. **Cloud (Gemini Model):** When an API key is available, queries are dispatched asynchronously to Google Gemini 3.1 Flash Lite API endpoint to perform advanced situational analysis and propose dynamic system reactions.
2. **Local Fallback (Tier-2 rules engine):** If the network is offline or no API credentials are provided, `AiService` automatically falls back to a local, deterministic rules engine. This produces matching JSON schemas using template-defined safety heuristics.

## Actions Proposing Safety Schema
All actions generated by the AI are validated against the central action schema:
- `dispatch_rover`
- `recall_rover`
- `set_zone_status`
- `set_alarm`
- `tune_threshold`
- `focus_ui`
- `set_layout`

Critical commands (such as alarm triggers) are gated behind manual operator approval, while lower-risk telemetry adjustments and UI focus actions are executed automatically.
